# Управляемые E2E-данные

Тесты могут работать с существующим dev-стендом, но сценарии live/history/video становятся стабильнее на специально подготовленных данных. Seed-скрипт создаёт только объекты с префиксом `e2e-` и отказывается изменять другие буровые.

## Что создаётся

- `e2e-main` — current-значения и история за 31 день;
- `e2e-no-video` — буровая без камер для проверки empty state;
- `e2e-video` — камера, если указан `E2E_VIDEO_WS_URL`;
- теги `e2e-depth`, `e2e-pressure`, `e2e-live`;
- почасовая история за месяц и пятиминутная история за последние сутки.

Точные ID можно переопределить через `E2E_EDGE_ID`, `E2E_NO_VIDEO_EDGE_ID` и `E2E_VIDEO_EDGE_ID`, но каждый ID обязан начинаться с `e2e-`.

## Подготовка

В `.env` укажите доступную из вашей среды строку подключения:

```dotenv
E2E_DATABASE_URL=postgresql://user:password@host:5432/app
E2E_INGEST_API_KEY=
E2E_VIDEO_WS_URL=wss://example.test/video/e2e
```

Создать или обновить данные:

```bash
bash scripts/seed-test-data.sh
```

Публиковать меняющееся значение `e2e-live` пять минут:

```bash
bash scripts/publish-live-data.sh --duration 300
```

Удалить только созданные E2E-данные:

```bash
bash scripts/seed-test-data.sh cleanup
```

## Учётные записи для проверки ролей

Для полного набора нужны три отдельные учётные записи Keycloak:

- администратор с ролью `drill-admin`;
- пользователь с ролью `drill-edge-e2e-main` и без доступа к `E2E_FORBIDDEN_EDGE_ID`;
- пользователь без ролей Drill Cloud.

Имена и пароли задаются переменными `E2E_ADMIN_*`, `E2E_EDGE_*` и `E2E_NO_ROLE_*`. Если пара не задана, соответствующий тест честно помечается `SKIPPED`.

Настройки UI тестируются раздельно для пользователей и всегда восстанавливаются в `finally`, поэтому прогон не оставляет изменённые настройки на стенде.
